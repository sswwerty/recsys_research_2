# RL для последовательных рекомендаций на Yambda

Проект по заданию № 2 T-Lab AI Research. Я проверила, что происходит с рекомендательной моделью на основе GPT-2, если после обучения на следующий трек дообучить её по прогнозу пользовательского отклика.

**Основной отчёт: [Отчет.pdf](<Отчет.pdf>)** 

## Что получилось

- **Базовая модель:** GPT-2 обучена с нуля на ID треков. Тестовый NDCG@10 равен 0.01851 против 0.00487 у рекомендаций по популярности.
- **Reward model:** прогнозирует долю прослушивания по истории и кандидату. RMSE на отложенных взаимодействиях — 0.36370; у среднего прошлого отклика — 0.38040. По MAE простой контроль оказался лучше.
- **RL:** проведено 18 запусков с разными наградами, KL-штрафами и seeds. У выбранной на валидации модели прогноз награды вырос с 0.6794 до 0.6884, а NDCG@10 — с 0.01851 до 0.01856. Доверительный интервал изменения NDCG включает ноль: убедительного улучшения релевантности не получено.
- **Пять шагов генерации:** обнаружены частые повторы и рост оценки RM при добавлении её собственных прогнозов в историю. Запрет дублей помогает, но не устраняет всё отставание от обычного Top-5.

Для эксперимента выбраны 1 000 пользователей Yambda со всей доступной историей. Модель работает с 5 000 треков из обучающего периода; обучение использует 100 000 целей. Время разделено глобально, словарь и статистики строятся по train. Тестовые цели вне каталога сохранены и дают ноль в основных метриках. Рост прогнозируемой награды не означает измеренного роста удовлетворённости или возвращаемости пользователей.

## Как запустить

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pytest -q
python run.py doctor
```

Датасет [Yambda-50M](https://huggingface.co/datasets/yandex/yambda) скачивается автоматически (около 352 MiB).
